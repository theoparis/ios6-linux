# Prior art: iOS 6 (ARMv7) recompiler + Wine-style runtime on x86-64 Linux

Engineering lessons from the projects that have already solved adjacent problems. Each section states what the project is, its architecture (5-10 lines), its exact license and whether we may link/copy, ideas to steal, traps observed, and its usefulness today. Claims about source are pinned to files; `UNVERIFIED:` marks things I could not confirm from primary sources in this pass.

## 0. Target facts that constrain every section

- Device in-repo: `iPad2,1_6.1.3_10B329_Restore.ipsw`; its flash images are `s5l8940x` (`applelogo.s5l8940x.img3`), i.e. Apple A5 / Cortex-A9 / **ARMv7-A**, 32-bit, 4 KiB pages. `armv7s` (A6, core name "Swift", e.g. `arm/string/bcopy_Swift.s` in iOS-6-era `Libc`) is a later delta (VFPv4, `idiv`, NEON). [INFERENCE from IPSW filenames + `apple-oss-distributions/Libc` tag `Libc-825.26`]
- iOS 6 is **dyld2**: the iOS-6-era open-source tags are `dyld-239.3` / `dyld-239.4` (`https://github.com/apple-oss-distributions/dyld/tree/dyld-239.3`), with `src/ImageLoaderMachOCompressed.cpp` (classic `LC_DYLD_INFO` rebase/bind opcodes), `src/stub_binding_helper.s` (lazy `dyld_stub_binder`), and `src/dyld.cpp`. No chained fixups, no dyld4, no `LC_DYLD_EXPORTS_TRIE`.
- System dylibs live in the device shared cache; this IPSW's extracted rootfs contains `System/Library/Caches/com.apple.dyld/dyld_shared_cache_armv7` (235.4 MB, only the armv7 slice). Apps bind to cache dylibs by install name. We must satisfy those symbols with our own dylibs or by reading the cache — never by shipping Apple images.
- App Store binaries are FairPlay-encrypted (`LC_ENCRYPTION_INFO.cryptid == 1`); a plaintext loader cannot see code until the user decrypts (§8).
- Runtime surface: Objective-C 2.0, GCD (`libdispatch`), UIKit, CoreAnimation, OpenGL ES 2.0 (many titles), OpenAL/AudioToolbox, `mach_msg`.

## 1. Darling — macOS binaries on Linux

Repo: <https://github.com/darlinghq/darling> (13.5k stars, last push 2026-10; latest release `v0.1.20260608`). It is the closest existing "Wine for a Mach-O OS", and it is a design reference, not a code source.

**Architecture**

- `mldr` is an **ELF** executable (`src/startup/mldr/mldr.c`) that parses Mach-O/fat, maps segments, loads Apple's `dyld`, and jumps into it. It currently accepts only `CPU_TYPE_X86` — Darling has no ARM path at all (`mldr.c` `load(filename, CPU_TYPE_X86, ...)`).
- `elfcalls` (`src/startup/mldr/elfcalls/elfcalls.c`) exposes host ELF `dlopen/dlsym`/pthread pointers to Mach-O code via a struct passed in the `apple` env array; `src/libelfloader/wrapgen/` generates Mach-O symbol resolvers that forward to host ELF symbols.
- `libsystem_kernel.dylib` is Apple's libsyscall, forked in `darling-xnu` at `darling/src/libsystem_kernel/`; the syscall macro is replaced by an emulation layer (`emulation/include/xnu_syscall/bsd/bsd_syscall_table.h`, `conversion/*`) that dispatches BSD/Mach/machdep calls. Per <https://docs.darlinghq.org/internals/basics/system-call-emulation.html>, Apple's wrappers are kept so the ABI matches macOS.
- `darlingserver` (<https://github.com/darlinghq/darlingserver>, submodule `src/external/darlingserver`) is the "userspace kernel server (much like Wine's wineserver)". The listener is `AF_UNIX SOCK_DGRAM` with `SO_PASSCRED` on one socket plus per-thread addresses and an `epoll` loop (`src/server.cpp`); FD transfer is `SCM_RIGHTS`. Client/server RPC stubs are generated by `generate-rpc-wrappers.py`; docs: <https://docs.darlinghq.org/internals/darlingserver/rpc.html>.
- Mach ports, port rights, message queues and MIG-style behavior are implemented by vendoring XNU (`darlingserver/duct-tape/xnu/osfmk/ipc/ipc_*.c`, `ipc_kmsg.c`, `ipc_mqueue.c`, `ipc_right.c`), not by emulating sockets: `mach_msg` is redirected into the server RPC world. The guest's port namespace is the XNU `ipc_space`.
- kqueue is XNU's own code duct-taped in (`duct-tape/src/kqchan.c`, `filt_machport*`) over epoll/eventfd; locks/condvars are XNU waitqs on top of Linux futexes (`duct-tape/src/locks.c`). The server also runs user-space **microthreads (fibers)** with cooperative scheduling rather than one Linux thread per guest thread (`docs/internals/darlingserver/index.html`).
- Prefixes are containers: the `darling` binary creates a mount namespace, an **overlayfs** of the read-only root with the prefix, "vchroot" (`src/vchroot/vchroot.c`, escape hatch `/Volumes/SystemRoot`), and a PID namespace with `launchd` as init (<https://docs.darlinghq.org/internals/basics/containerization.html>).
- 32-bit commpage is synthesized at `0xffff0000`; entries include CPU info and time fallbacks (<https://docs.darlinghq.org/internals/macos-specifics/commpage.html>).

**License** — Root `LICENSE` is **GPL-3.0**; README states "individual submodules may be licensed differently". `darlingserver` sources carry GPLv3 headers (e.g. `src/call.cpp`). Darling's forks of Apple code (`darling-xnu`, `darling-dyld`) carry **APSL-2.0** (`APPLE_LICENSE`), and `src/external/libdispatch` is Apache-2.0. We cannot link/copy GPLv3 or APSL code into a non-GPL runtime; **process separation is an architectural boundary, not a license shield** — copying server code into our process tree is still copying. Concepts and the documented RPC wire format are reusable; the code is not.

**Adopt** — the process-separate kernel server with generated stubs; one endpoint per guest thread; `SCM_RIGHTS` for FDs/ports; process-lifetime pipes to detect death; per-thread commpage; "elfcalls": a table of host function pointers handed to recompiled guest code so host libs (GLES, audio, Skia) are reached without a Mach-O-side ELF loader; user-visible prefix as an overlay root; and the discipline of keeping Apple open-source pieces in a quarantined directory with explicit license headers.

**Traps** — (a) the original Linux-kernel-module approach (`darling-mach`) was unstable and hard to debug; darlingserver replaced it after years; (b) because `libsystem_kernel` and `dyld` are replaced, software making raw syscalls breaks (documented), and a "full macOS copy" is impossible; (c) x86-only loader (`CPU_TYPE_X86`), so nothing here covers ARMv7; (d) GUI is the long tail: the non-functional list (<https://docs.darlinghq.org/known-nonfunctional-software.html>) names XQuartz, Xcode GUI, most toolkits, and "any complex GUI application"; AppKit via Cocotron was a decade-scale sink; (e) mixing GPLv3 and APSL-2.0 makes downstream licensing messy — exactly what we must avoid.

**Maturity** — CLI is real: Homebrew, Emacs, Python 3, CMake, gnuplot, Xcode command-line tools run (<https://docs.darlinghq.org/known-working-software.html>); simple GUIs mostly do not. It proves kernel-server + framework-reimplementation works on Linux, and shows the 10-year cost of chasing a desktop GUI stack.

**Not needed for iOS** — Cocoa/AppKit/Cocotron, X11/ALSA/DBus glue, macOS `dyld3/4` shared-cache machinery, the x86_64/i386 focus, `.dmg`/`.pkg` install tooling. iOS 6 needs UIKit + GLES2 + GCD instead.

## 2. touchHLE — early iPhone OS apps on modern hosts

Repo: <https://github.com/touchHLE/touchHLE> (4k stars, v0.3.0 Oct 2026: "iOS 4.0 and iPad support"; written in Rust; the README says iOS 5/6 is a long-term goal and **64-bit is never**). This is the most directly relevant runtime implementation.

**Architecture**

- CPU: **dynarmic** A32 via a thin C++ wrapper (`src/cpu.rs`, `src/cpu/dynarmic_wrapper/lib.cpp`). The README/docs say only **ARMv6 has been tested**; iOS 4 support implies ARMv7 partially works, but ARMv7-A/NEON/VFP coverage is not a project claim. `CpuContext` = `regs[16] + extregs[64] + cpsr + fpscr` (`lib.rs`).
- Memory: one flat **4 GiB** host mapping so guest VA == host VA: `type Bytes = [u8; 1 << 32]` (`src/mem.rs`), mmap'd with lazy pages, 4 KiB `PAGE_SIZE`, `VMAllocator` covering all of 32-bit space, a 1 MiB main-thread stack at the top (`MAIN_THREAD_STACK_LOW_END`), 512 KiB default secondary stacks, 16-byte-minimum heap, and a null segment where accesses are trapped. dynarmic is configured with `absolute_offset_page_table` pointing into this mapping, so ordinary loads/stores compile to direct host memory accesses and only faulting/null pages hit callbacks (`lib.cpp` `page_table`, `check_halt_on_memory_access`).
- Objective-C: a complete host-side runtime (`src/objc/*`). Classes are either host implementations (Rust `IMP`s) or guest classes parsed from Mach-O metadata; `msg_send` walks the superclass chain over `HashMap<SEL, IMP>` (`src/objc/messages.rs::objc_msgSend_inner`). Host IMPs are called through `CallFromGuest`; guest IMPs are tail-called **without a new stack frame** so surplus stack arguments are not disturbed. `objc_msgSend_stret`, `objc_msgSendSuper2` and `+initialize` (with an emulated pthread mutex/cond) are handled. There is **no method cache** (`_cache` in `class_t` is unused) and type checking is optional/tolerant.
- Host↔guest calls: `src/abi.rs` sets LR to a `return_to_host_routine` sentinel, pushes a fake guest frame for traces, and runs `env.run_call()` until the sentinel returns; a Rust macro implements `CallFromHost` for 0..8 register args plus stack spill (only 4 integer arg registers on ARM).
- Threading: each guest thread is a **`corosensei::Coroutine`** holding its own CPU context, guest stack range and framework thread-local state (`src/environment.rs` `Thread`). Exactly one guest thread executes at a time; blocking operations (mutex, cond, semaphore, sleep, join, file locks) yield to the scheduler. Guest compute is never preempted.
- Frameworks: UIKit/CoreFoundation/CoreGraphics/CoreAnimation/OpenGL ES/OpenAL/AudioToolbox/etc. are reimplemented in Rust (`src/frameworks/`). Unimplemented classes panic with names; "fake" classes return nil. This is strict HLE: no Apple framework code runs.
- Rendering: SDL2 window (`src/window.rs`), an OpenGL ES 1.1 abstraction with two backends — native GLES1.1 (`src/gles/gles1_native.rs`) or GLES1-on-GL2.1-compat (`src/gles/gles1_on_gl2.rs`) — plus `present.rs` for frame presentation, touch cursor, splash and CA layer compositing.

**License** — **MPL-2.0** (repo `LICENSE`, `Cargo.toml` `license = "MPL-2.0"`). MPL is file-level copyleft: we may link it as a library and may copy files if we keep MPL-2.0 on those files and publish their source. It is GPL-compatible by default (no "Incompatible With Secondary Licenses" notice found in the sources). dynarmic itself is **ISC** (`LICENSE.txt`: "Permission to use, copy, modify, and/or distribute ... with or without fee"), so the CPU core is permissive; SDL2 is zlib; text/audio libs have their own licenses.

**Adopt** — the whole HLE shape (app code + a few guest dylibs run; iOS is replaced); own ObjC runtime where host and guest classes coexist; host-IMP dispatch on `objc_msgSend`; sentinel-return guest calls; **flat 4 GiB guest memory with guest VA == host VA and a page-table fast path**; coroutine guest threads with explicit block points; native framework implementations that fail loudly on unimplemented selectors; per-file license hygiene.

**Traps** — (a) the cooperative single-threaded scheduler can stall when guest threads busy-wait or use lock-free/GCD patterns; it works for the single-threaded games touchHLE targets, not necessarily for iOS 6 apps; (b) **no method cache**: every message walks the superclass chain and does a hash lookup — fine for 2010 games, not for an OS-scale workload; (c) ARMv6-tested/GLES1.1-only, while iOS 6 means ARMv7 + VFP/NEON + GLES2 + GCD; (d) `check_halt_on_memory_access` exists to catch null-page faults and is noted in-source as "surely a significant performance impact"; (e) `+initialize` reimplements pthread locking out of necessity — a hint that threading emulation is load-bearing; (f) coverage is explicitly partial: the README says most iOS 2.x–4.x apps do not work and UIKit is "the most hacky and incomplete" framework.

**Maturity** — active, released (v0.3.0), crowdsourced compatibility DB, strong on early games; treats iOS 5/6 as future work, so its framework inventory is a starting checklist, not a solution.

## 3. QEMU user-mode (`linux-user`)

Repo: <https://gitlab.com/qemu-project/qemu>; docs: <https://www.qemu.org/docs/master/user/main.html>. Supported user-mode OSes are Linux and BSDs — **there is no Darwin/Mach-O user target today**.

**Architecture**

- Loader: `linux-user/elfload.c` (`load_elf_image`, `load_elf_binary`) handles `PT_LOAD`/`PT_INTERP`, builds the initial stack and auxv; per-arch `linux-user/<arch>/elfload.c` (e.g. `linux-user/arm/elfload.c`) adds hwcaps/cpu-model specifics.
- Syscalls: `do_syscall()` in `linux-user/syscall.c` (~14.5k lines) is the translation layer: a `switch` over `TARGET_NR_*` constants generated per target from `linux-user/<arch>/syscall*.tbl` via `syscallhdr.sh`, with target↔host struct/errno/`ioctl`/`stat`/`sockaddr` conversion helpers and guest-memory accessors (`lock_user`, `copy_from_user`). `linux-user/<arch>/cpu_loop.c` decodes the trap (e.g. ARM `svc`/`r7`) and calls `do_syscall`. `-strace` is implemented by `linux-user/strace.c` + generated `strace.list`, printing decoded syscalls (`linux-user/main.c::handle_arg_strace`).
- TCG: the translator IR lives in `tcg/`; ARM lowering is `target/arm/tcg/translate.c`. `accel/tcg/translate-all.c::tb_gen_code` allocates/translates translation blocks; `accel/tcg/cpu-exec.c` does `tb_lookup`, executes, and patches direct jumps with `tb_add_jump`/`tb_set_jmp_target` (runtime TB chaining); `accel/tcg/tb-maint.c` handles invalidation. Caches are **in-memory only**; there is no on-disk code cache.
- Tracing: `-d in_asm` logs guest assembly and `-d cpu` dumps CPU state (`util/log.c` items; `accel/tcg/cpu-exec.c::log_cpu_exec`), and `-d exec,nochain` toggles chaining — a ready-made differential-testing instrument.
- One target arch/OS is compiled in; QEMU is not a runtime-pluggable multi-OS emulator, and `linux-user` hardcodes Linux ABI at build time.

**What a Mach-O front end would require** — a Mach-O/fat loader (`LC_SEGMENT*`, `LC_DYLD_INFO_ONLY` rebase/bind opcodes, `LC_SYMTAB`/`LC_DYSYMTAB`, `LC_LOAD_DYLINKER`, `LC_MAIN`, `LC_UNIXTHREAD`, `LC_ENCRYPTION_INFO`), dyld2 eager/lazy binding with `dyld_stub_binder`, Apple ARMv7 syscall decode (`svc` + XNU's BSD/Mach/machdep multiplexing — not Linux numbers), Darwin struct/errno conversion, `bsdthread_*`/machdep traps, Mach traps and MIG messages, Mach exceptions and Darwin `sigreturn` frames, commpage, CP15 TLS, `mach_vm_allocate`/4 KiB `mmap` semantics, and code-signature/entitlement blob parsing. QEMU shares only TCG/TB machinery; every loader/syscall/signal line must be new. **QEMU already had exactly this**: the `darwin-user/` directory (`machload.c`, `commpage.c`, `mmap.c`, `syscall.c`, `main.c`) existed in old QEMU and was proposed for deletion in 2012 and dropped (see <https://qemu.googlesource.com/qemu/+/c5bac30252cc06d226bb7d57e40cdee5a532a4c8/darwin-user> and the `[RFC 07/14] Drop darwin-user` thread on qemu-devel). It bit-rotted; that is the cautionary tale for a one-person Mach-O front end.

**License** — **GPL-2.0-or-later** (`SPDX-License-Identifier: GPL-2.0-or-later`, e.g. `linux-user/arm/elfload.c`; `COPYING`). Reusing TCG or `linux-user` code forces GPL-2.0-or-later on the combined work and is incompatible with APSL-2.0 and with GPLv3-only pieces; if our runtime is permissive, QEMU can only be an out-of-process oracle. TCG is not LLVM: no AOT, no persistent cache, LLVM-quality optimization is unavailable.

**Adopt** — `-d in_asm,cpu` + `-strace` as the model for trace capture and diffing; TB chaining and per-page invalidation as baseline; generated per-arch syscall tables; allocator/syscall discipline; the `darwin-user` file list as a work breakdown and a warning about scope.

**Traps** — monolithic switch + per-arch `#ifdef` soup; Linux ABI assumptions everywhere; no persistent translation; TCG is a generic baseline (slower than purpose-built dynarecs); adding an OS ABI to `linux-user` is not a supported extension point.

**Maturity** — extremely mature for Linux/BSD user emulation (qemu-user-static underpins multi-arch containers); the Darwin path is dead.

## 4. Unicorn

Repo: <https://github.com/unicorn-engine/unicorn> (9.4k stars, active 2026). The prompt's "QEMU core + Capstone" needs one correction: Unicorn **forks QEMU's TCG/softmmu** and does **not** embed Capstone (only a CMake `# Source:` comment references it; the FAQ mentions "remove additional use of capstone" in the context of Unicorn's own tree). Capstone is a separate disassembler by the same author and is normally *paired with* Unicorn.

**What it is / API**

- `uc_open(UC_ARCH_ARM, UC_MODE_ARM|UC_MODE_THUMB|UC_MODE_LITTLE_ENDIAN, &uc)`; `uc_mem_map`/`uc_mem_map_ptr`/`uc_mem_regions`; `uc_mem_read`/`uc_mem_write`.
- `uc_emu_start(begin, until, timeout, count)` — `count == 1` is single-step; `uc_ctl_exits_enable` + an exits array lets you stop at chosen PCs; `uc_emu_stop` from a hook.
- `uc_reg_read/write` for `UC_ARM_REG_R0..R15`, `CPSR`, `SPSR`, `D0..D31`, `FPSCR`, plus `uc_reg_read_batch`; **full dumps** via `uc_context_alloc`/`uc_context_save`/`uc_context_restore` (`include/unicorn/unicorn.h`).
- Hooks: `UC_HOOK_CODE`, `UC_HOOK_BLOCK`, `UC_HOOK_MEM_READ/WRITE/READ_AFTER`, `UC_HOOK_INTR`, with range filtering; hooks are the only fault mechanism.
- `uc_ctl` provides `UC_CTL_CPU_MODEL` (`UC_CPU_ARM_CORTEX_A8/A9/A15`, ...), `UC_CTL_TB_REMOVE_CACHE` / `uc_ctl_remove_cache` / `uc_ctl_flush_tb` for self-modifying code, and page-size control.
- ARM: `UC_ARCH_ARM` covers ARM/Thumb/Thumb-2; Thumb requires `UC_MODE_THUMB` **and an odd start address** (FAQ); VFP/NEON may need CPACR/FPEXC setup; CPU model changes which instructions are accepted (FAQ #1724/#1725). Coprocessor registers are reachable via `UC_ARM_REG_CP_REG`.

**Limitations for our purposes** — no OS, no syscalls, no Mach-O; no exception/precise-fault model (SVC only via `UC_HOOK_INTR`); block-granular execution unless you use `count`/hooks; per-instruction hooks are expensive; MMU support is partial/recent (`uc_vmem_read`); no cycle-accurate timing; it pins an older QEMU fork, so ARMv7/VFP/NEON behavior must be validated against real hardware for anything you rely on.

**License** — **GPL-2.0** (`COPYING`, README) with LGPL-2.0 API headers. Linking Unicorn into a permissive runtime is not viable; if the project must stay permissive, run the oracle out-of-process or keep it as an optional test-only dependency. Capstone is **BSD-3-Clause** (`LICENSES/LICENSE_BSD_3_CLAUSE.txt`) and can be linked freely.

**Adopt** — as the differential-testing oracle: per-instruction stepping, full context save/restore, memory compare, hook-based trace; fuzzing ARMv7 encodings and flag-setting instructions; using `UC_ERR_INSN_INVALID` to find instructions our lifter mishandles; Capstone for disassembly diffs. Keep it out-of-process to avoid the license becoming contagious.

**Traps** — treating it as a system emulator; forgetting CPU model/FP enablement then blaming Unicorn for invalid instructions; assuming Unicorn's fork of QEMU has the same ARM semantics as current QEMU; using it as the production CPU (its performance and fault model are not suited to a full OS ABI).

**Maturity** — the de-facto standard for instrumented CPU emulation in security/RE; excellent oracle, poor runtime base.

## 5. FEX-Emu, Box64/Box86 — production x86-64→ARM64 emulators

Both are MIT, both run real AAA games, both hand-write their backends (no LLVM), and both lean on host library forwarding. They are the best evidence for what a *fast* user-mode recompiler needs.

### 5.1 FEX-Emu (`FEX-Emu/FEX`, MIT, 8.3k stars)

- **IR + backend**: custom SSA IR generated from x86-64 (`FEXCore/Source/Interface/IR/IR.json`, `IntrusiveIRList.h`, docs `FEXCore/docs/IR.md`) with explicit context load/store ops (guest state separate from locals), an explicit syscall op, and a hand-written ARM64 "splatter" backend that concatenates macro-emitters per op (`FEXCore/Source/Interface/Core/JIT/*.cpp`, `ArchHelpers/Arm64Emitter.cpp`). No LLVM anywhere in codegen.
- **Guest-register caching**: guest GPRs/XMM live in a pinned per-thread context; the SSA register allocator maps values to host registers with spill slots (`IR/Passes/RegisterAllocationPass.cpp`, rewritten in FEX-2406 after the original RA could be quadratic/infinite — see <https://fex-emu.com/FEX-2406>). Guest state is only read/written through explicit context ops, so the RA owns host registers.
- **Flags**: x86 flags are **deferred/lazy** — `OpcodeDispatcher/Flags.cpp` computes flags on demand (`CalculateDeferredFlags`, `SetRFLAG<…>`), and the IR pass `RedundantFlagCalculationElimination.cpp` tracks per-flag read/write sets and deletes dead flag math. FEX also has a whole config surface for TSO/memory-model emulation (`TSOEnabled`, half-barrier atomics, `HalfBarrierTSOEnabled`, `VolatileMetadata`) because x86-TSO on ARM is the single biggest correctness/perf axis (`FEXCore/Source/Interface/Config/Config.json.in`).
- **Block cache / linking**: `LookupCache.cpp` allocates a page-indexed guest→host map (`PageMemoryMap[VA >> 12] → PageMemory[...] → code ptr`) plus a `GuestToHostMap` for linking; `CodeCache.cpp` handles invalidation under a write-priority mutex. **SMC** is handled by `SMCChecks`: default `mtrack` (page tracking), `full` (validate before every run, slow), `none`; Unity/Mono get a hook-based hack (`MonoHacks`) and FEX-2609 notes a faster "full" check for Unity (blog: <https://fex-emu.com/FEX-2609>).
- **Thunks**: `ThunkLibs/README.md` documents guest stubs using opcode `0F 3F` (`OP_THUNK`) + opcode-embedded `library:function` string, generated packers/unpackers, host `dlopen`, a `fex:loadlib` bootstrap, and host→guest callbacks. `Data/ThunksDB.json` overlays host libs (GL, Vulkan, drm, asound, ...).
- **Persistent cache**: `DiskCache.cpp` / `CodeCache.cpp` store JIT code in a **FOZ (Fossilize) database**, looked up before JITing; the FEX-2609 post admits early limitations: unbounded growth for JIT-ing apps and no invalidation when file contents change.
- **Perf**: vendor claims are "near native" with new register allocator + AFP/RPRES (+2–12%) and 32-bit OpenGL thunking taking one game 150→270 FPS (`FEX-2406`). Treat as vendor benchmarks; the point is that CPU-bound is where emulation cost lives, GPU-bound is where thunking hides it.

**Adopt** — SSA IR with optimization passes *before* host codegen (even when the final backend is LLVM); explicit guest-state ops; deferred flags + dead-flag elimination; page-indexed block map + direct linking; generated thunk layers; disk cache keyed by code hash + settings + host CPU; memory model emulation as a tunable.

### 5.2 Box64 (`ptitSeb/box64`, MIT, 5.7k stars) / Box86 (MIT)

- **Dynarec**: interpreter plus hand-written dynarec per host arch (ARM64/RV64/LoongArch/PPC64LE), multi-pass with per-opcode emitters (`src/dynarec/<arch>/dynarec_*.c`, passes `dynarec_native_pass.c`, `pass0..pass3`). No IR framework, no LLVM.
- **Guest-register caching**: each block's per-arch private state tracks which guest GPR/XMM/x87/MMX values are currently live in host registers, with explicit `neoncache`/`ssecache`/`x87cache`/`mmxcache`/`flagcache_t` status arrays and spill/reload at block boundaries (`src/dynarec/arm64/dynarec_arm64_private.h`); passes pass0..pass3 assign registers (`dynarec_native_pass.c`).
- **Flags**: deferred flags (`BOX64_DYNAREC_DF`), native-flag reuse where the host has compatible flags (`DYNAREC_NATIVEFLAGS`), and `SAFEFLAGS` policy for CALL/RET edge cases (`docs/USAGE.md`).
- **Block linking / SMC**: `src/dynarec/dynablock.c` + `dynarec_native.c::add_next` implement "next"/big-block chaining; SMC is detected via write-protected pages plus signal handling (`src/libtools/signals.c`, `sigtools.c` `is_addr_autosmc`, `BOX64_DYNAREC_DIRTY`, `BOX64_DYNAREC_NOHOTPAGE`).
- **Persistent cache**: **DynaCache** is on by default, writes compressed files under `~/.cache/box64`, with a size limit (default 2048 MiB) and LRU eviction (`README.md`, `docs/USAGE.md`, `src/include/dynacache.h`).
- **Library forwarding**: "the twist" — wrapped libraries map guest calls to host `.so` functions (`src/librarian/library.c`, `library_list.h`, `src/wrapped/wrappedlibc.c`). Missing wrappers fall back to emulated libs (slow).
- **Perf** (vendor): CPU-bound ~50% native, graphics-bound near 100% because of wrapped libs; OpenArena measured 80–85% native on RK3399 (<https://box86.org/index.php/2021/06/game-performances/>). A EuroSys 2026 paper is cited from the README for internals.

**Adopt** — deferred flags with explicit "flags dirty" state; a persistent cache with eviction policy; page-protection-based SMC detection with a "dirty/hot page" heuristic; library forwarding as the primary performance strategy for graphics/audio/network.

**Traps in both** — per-host hand-written backends are an enormous maintenance surface; SMC heuristics are a correctness risk (Box64 exposes "allow dirty block" escape hatches; FEX's `full` check is slow); persistent caches need invalidation keys or they serve stale code; per-app hacks accumulate. Also note the asymmetry for us: ARMv7→x86-64 goes *weak→strong*, so over-ordering is mostly safe, but ARM exclusives (`LDREX/STREX`), `DMB/DSB/ISB`, and code that relies on weak ordering still need explicit handling.

## 6. Other LLVM-based / production recompilers

**RPCS3** (GPL-2.0-only per `README.md`; <https://github.com/RPCS3/rpcs3>). PPU: `Emu/Cell/PPUTranslator.cpp` lifts PowerPC to LLVM IR; a `jit_compiler` compiles modules to **relocatable LLVM objects cached on disk** named `cache/<titleid>/ppu-<base57 sha1>-<name>/v9-kusa-<hash>-<settings>-<llvm-cpu>.obj` (`Emu/Cell/PPUThread.cpp` around the `ppu_initialize2`/`jit_compiler::check`/`add` calls), with `.log` dumps. Dispatch is a guest-address→host-function pointer table in `vm::g_exec_addr` (`ppu_ptr`, `ppu_cache`, `ppu_recompiler_fallback`) rather than TB chaining. SPU: LLVM and ASMJIT backends (`SPULLVMRecompiler.cpp`, `SPUASMJITRecompiler.cpp`) plus a raw-program cache `spu-<blocksize>-v1-tane.dat` (`SPUCommonRecompiler.cpp`). Lesson: cache generated objects keyed by **module hash + settings + LLVM CPU**, and separate "what to recompile" (raw program discovery) from "compiled code".

**Ryujinx** (MIT; upstream shut down Oct 2024, mirrors at `git.yurzs.dev/archive/ryujinx` and forks like Ryubing). ARMeilleure translates ARM64 to a custom SSA IR (`SsaConstruction.cs`/`SsaDeconstruction.cs`) then emits ARM64/x86 (`CodeGen/*`); `Translation/Cache/JitCache.cs` reserves a **2 GiB** code region with `CacheEntry` metadata; `Translator.cs` compiles functions and supports **rejit** — after 100 calls (`MinsCallForRejit`) a function is recompiled with `CompilerOptions.HighCq`. **PPTC** (`Translation/PTC/Ptc.cs`) writes compressed code, relocations and unwind info with outer/inner magic (`PTCohd`/`PTCihd`) and an internal version, keyed by title ID/version + translation hash; `PtcProfiler.cs` selects hot functions; `EncodingCache.cs` dedupes. Lesson: profiled persistent cache + tiered rejit + explicit version/hash invalidation.

**Yuzu** (reported GPL-3.0; upstream removed 2024 — `UNVERIFIED:` against a live LICENSE file). Uses **dynarmic** for ARM64/ARM32 on x86 hosts and native code execution (NCE) on ARM64 hosts; no on-disk CPU translation cache was exposed in shipped builds (shader cache only; the CPU cache dies with the process) — `UNVERIFIED:` against the final tree, since the upstream repo is gone and mirrors differ. Lesson: on hosts that can execute guest code natively, don't translate; for our x86-64 host that option does not exist, so the cache/tier design must come from Ryujinx/RPCS3 instead.

**Dolphin** (GPL-2.0-or-later per `COPYING`; <https://github.com/dolphin-emu/dolphin>). Hand-written `Jit64` (`Source/Core/Core/PowerPC/Jit64/Jit.cpp`) and `JitArm64`; `JitCommon/JitCache.cpp` implements the block cache: `block_map` (physical address→`JitBlock`), a fast lookup table indexed by address + feature flags, reverse `links_to` (destination→source blocks), `block_range_map` in 0x100-byte macro blocks, and `LinkBlock`/`UnlinkBlock`/`WriteLinkBlock` that patch direct branch instructions into linked blocks on hit. Cache is **in-memory only**; icache flushes invalidate blocks. The LLVM-based `JITIL` was removed years ago. Lesson: separate *feature flags* (FPU/model state) into block identity, and keep a reverse link map to unlink quickly on invalidation.

**Dynarmic** (ISC; <https://github.com/yuzu-mirror/dynarmic>). A32 (ARMv6K-ish; the `docs/Design.md` says "dynamic recompiler for the ARMv6K architecture") and A64 frontends → IR (`src/dynarmic/ir/`), optimization passes (`src/ir_opt/`), x64 and ARM64 backends; `UserCallbacks::MemoryReadCode` supplies code bytes; `Jit::Execute` runs blocks. It is the engine behind touchHLE and Yuzu. For us it is a candidate tier-0 engine or an oracle, but its A32 coverage/ARMv7-NEON completeness must be measured before betting on it (`UNVERIFIED:` exact ARMv7-A feature coverage).

**machismo** (GPL-3.0; <https://github.com/bmdhacks/machismo>). Not a recompiler: it loads **arm64** Mach-O on aarch64 Linux, patches chained fixups into GOT entries via `dlopen/dlsym`, and shims Apple ABI mismatches: C++ ctor ABI, `std::string` SSO layout, pthread object ABI, zeroed malloc, compact-unwind→DWARF, TLV, commpage, libSystem. Useful as a checklist of Mach-O/ABI traps and as a demonstration that "load Mach-O + redirect to native libs" is viable when the ISA matches; it is arm64-only and no help for ARMv7 translation.

**Rosetta 2** (proprietary; <https://support.apple.com/en-gb/guide/security/secebb113be1/web>). x86-64→arm64 on Apple Silicon; **AOT on first launch plus JIT fallback**, an `oahd`-style daemon answering IPC queries for cached translations, artifacts under `/var/db/oah/`, and hardware memory-model assistance. Closed source, not redistributable, but the architecture is the right one for us: AOT/JIT hybrid, translation lookup service, content-addressed cache keyed by binary identity.

**Android `libndk_translation`** (Google, proprietary, no source; native-bridge docs at <https://android.googlesource.com/platform/art/+/main/libnativebridge/README.md>). ARM-on-x86 native bridge shipped as a black box; evidence that vendor-shipped ISA translation is viable, and a reminder that the binding layer (JNI, TLS, ABI, FD passing) is where most compatibility bugs live. Not reusable.

**"olive"** — no public ARMv7 recompiler of that name was findable (`UNVERIFIED:` likely a misremembering). `armvm` exists but is a small interpreter, not a recompiler.

## 8. Legal / EULA reality check

This is a non-lawyer summary of primary texts; treat it as risk identification, not advice.

- **iOS 6 SLA**: `APPLE iOS SOFTWARE LICENSE AGREEMENT, Single Use License`, §2(a): "you are granted a limited non-exclusive license to use the iOS Software on a single Apple-branded iOS Device"; §2(c): "You may not and you agree not to ... decompile, reverse engineer, disassemble, attempt to derive the source code of, **decrypt**, modify, or create derivative works of the iOS Software"; §3 forbids redistribution/sublicensing. Source: <https://www.apple.com/legal/sla/docs/ios6.pdf>. That license covers the OS; third-party apps come with their own EULAs plus the Apple Media Services terms, which are likewise hardware-bound. Running the OS on non-Apple hardware is outside the license; emulating an app on Linux is at best a contract gray area even when you own the app.
- **macOS SLA**: titled "For use on Apple-branded Systems"; single-copy per Apple-branded computer; virtualization allowed only on Apple-branded hardware (<https://www.apple.com/legal/sla/docs/macOSSequoia.pdf>). This is the clause that makes a "macOS-on-Linux" product a license breach (and it is why Darling requires you to bring your own Apple software and still only reimplements).
- **DMCA §1201**: decryption of FairPlay (`cryptid == 1`) is circumvention. The 2024 triennial rulemaking **renewed jailbreaking exemptions** for smartphones/portable devices, smart TVs, voice assistants, and routers (`37 C.F.R. § 201.40(b)(9)–(12)`; Register's Recommendation §I, <https://www.copyright.gov/1201/2024/2024_Section_1201_Registers_Recommendation.pdf>). Those exemptions allow circumvention *for jailbreaking the device*; they do **not** authorize redistributing decrypted apps or Apple binaries.
- **Decrypted binaries are required**: App Store binaries are FairPlay-encrypted, so a loader sees ciphertext until the user decrypts on a jailbroken device. touchHLE states plainly: "the app binary must be decrypted to be usable" and "Only use touchHLE to emulate software you have obtained legally" (<https://github.com/touchHLE/touchHLE>). It ships no Apple code and no apps. That is the community's standard posture: bring your own decrypted binary; the emulator is not a distribution channel. AppDB-style compatibility sites host metadata, not binaries.
- **What the accepted projects do**: Darling reimplements macOS user space, requires the user's own Apple software, and quarantines Apple open-source components under APSL (`README.md`: submodules may differ). touchHLE reimplements iOS frameworks and requires legally obtained, decrypted apps. Whisky (<https://github.com/Whisky-App/Whisky>) is a Wine/CrossOver + Game Porting Toolkit wrapper for *Windows* software on macOS — no Apple OS component runs; it is now unmaintained. CrossOver's marketing claim is "No Windows license needed" because Wine reimplements the Windows API and ships no Microsoft code (<https://www.codeweavers.com/>). The lesson: Wine-like projects are tolerated when they reimplement interfaces and ship no proprietary OS/firmware; they are on thin ice when they redistribute or decrypt someone else's binaries.
- **Case law worth knowing**: *Apple v. Psystar*, 658 F.3d 1150 (9th Cir. 2011) (and 658 F. Supp. 2d 1150 (N.D. Cal. 2009)) — the macOS EULA restricting installs to Apple hardware survived; Psystar lost on copyright/contract (<https://law.justia.com/cases/federal/district-courts/california/candce/3:2008cv03251/204881/242>). *Apple v. Corellium*, 11th Cir. 2023, No. 21-12835 — the district court's fair-use ruling for a virtualized-iOS security-research product was affirmed, but the DMCA §1201 claim was revived on appeal; the case is security-research-specific, not a consumer-emulation safe harbor (<https://law.justia.com/cases/federal/appellate-courts/ca11/21-12835/21-12835-2023-05-08.html>). API reimplementation for interoperability also has fair-use support (*Sega v. Accolade*; *Google v. Oracle*), but that protects reimplementation of interfaces, **not** shipping Apple code or decrypted apps.
- **Bottom line for us**: ship only our own code + permissively licensed dependencies; require the user to supply the IPSW and app binaries; never bundle Apple dylibs/dyld/shared cache, decrypted IPAs, firmware, or decryption keys; document that the user is responsible for their licenses; do not implement or ship a decryption tool; and keep the IPSW in the repo out of any distribution artifact (it is a user-provided input, and `*.ipsw` should anyway be gitignored).

## 9. Recommendations

### Steal these (12)

1. **Wine/Darling kernel-server split.** Put Mach ports, port rights, message queues, task/thread namespaces, and Darwin syscall state in a separate userspace server; use generated RPC stubs over `AF_UNIX` datagrams, one endpoint per guest thread, `SCM_RIGHTS` for FDs, and a lifetime pipe per process. Reimplement the protocol cleanly (do not copy GPLv3 darlingserver code).
2. **HLE the OS, LLE only the app.** touchHLE's model: the app's ARMv7 code plus a tiny set of guest dylibs execute; UIKit/Foundation/CF/CG/GLES are host code. This is the only path that avoids shipping Apple dylibs and the shared cache.
3. **Flat 4 GiB guest memory with guest VA == host VA.** `type Bytes = [u8; 1<<32]`, one `MAP_NORESERVE` mapping, 4 KiB pages, zeroed null page, page-table fast path into the JIT. It removes address translation from every memory op and matches the 32-bit guest exactly (touchHLE `src/mem.rs`).
4. **Own ObjC runtime with mixed host/guest classes + a host-IMP dispatch path**, including `objc_msgSend_stret` and `objc_msgSendSuper2`, `+initialize` locking, and guest-class metadata parsed from `__objc_*` sections. Read Apple's `objc-msg-arm.s` (`objc4-532`) to get the ARM ABI exactly right.
5. **Add a per-class method cache and a selector→IMP inline cache.** touchHLE walks the superclass chain every message; that is the single clearest performance upgrade for our scale.
6. **Sentinel-return guest calls.** Host functions call guest IMPs by setting PC/LR to a magic return address and running the JIT until it returns; preserves stack arguments and avoids unwinding through JIT frames (`touchHLE src/abi.rs`).
7. **SSA IR with passes before LLVM.** Even with LLVM 23 + ORC/JITLink, lift ARMv7 to our own SSA (loads/stores of guest state explicit, like FEX `IR.md`) so flag/register/dead-code passes run before the LLVM backend. Emit LLVM IR from optimized SSA; use JITLink for x86-64 relocatable objects.
8. **Deferred/lazy flags with dead-flag elimination.** ARM CPSR NZCV need not be materialized after every ALU op; keep `flags_dirty` + last operands, compute at branches/reads, and delete redundant flag math (FEX `Flags.cpp`, `RedundantFlagCalculationElimination.cpp`). x86 has `setcc/cmov` primitives that map well.
9. **Tiered codegen with a persistent cache.** Tier 0 interpreter/threaded code for correctness bring-up, tier 1 LLVM `-O1`, tier 2 `-O2` with cross-block inlining; persist LLVM objects/JITLink images with relocation+unwind data, keyed by guest-code hash + translator version + host CPU (RPCS3 `.obj` cache, Ryujinx PPTC, Box64 DynaCache). Include a profiler-driven recompile tier (Ryujinx's 100-call threshold is a good default).
10. **Host-library thunks.** Generate guest stubs that marshal into host GLES/audio/network/CoreGraphics implementations instead of emulating those libraries (FEX `ThunkLibs`, Box64 wrapped libs). For iOS 6 the high-value ones are GLES2 (ANGLE/Zink), CoreAudio/OpenAL, and CoreGraphics/CoreText (Skia/FreeType/HarfBuzz).
11. **Differential-test everything against Unicorn, out-of-process.** Single-step + `uc_context_save` + memory diff over fuzzed ARMv7 sequences; use QEMU's `-d in_asm,cpu` and `-strace` as the trace format; Capstone (BSD-3) for disassembly diffs; treat `UC_ERR_INSN_INVALID` as a coverage signal. Keep GPL tools out of our binary.
12. **Loader/dyld2 first, cache reader later.** Implement `LC_SEGMENT` mapping, `LC_DYLD_INFO_ONLY` rebase/bind, lazy binding via a `dyld_stub_binder` equivalent, `LC_MAIN`/`LC_UNIXTHREAD`, `LC_ENCRYPTION_INFO` detection, entitlements parsing, `@rpath/@loader_path`, and the iOS 6 commpage (0xffff0000, 32-bit). Use LLVM's `MachOObjectFile`/`MachO.h` for parsing/validation (Apache-2.0-with-LLVM-exception) and `dyld-239.3`'s bind-opcode decoder as the reference, but keep Apple images out of our runtime. Reading the device shared cache is a *symbol/type* source of last resort, not a code source.

### Do not do these (6)

1. **Do not link or copy GPL/APSL code into the runtime.** Darling (GPLv3), QEMU (GPL-2.0-or-later), Unicorn (GPL-2.0), RPCS3/Dolphin (GPL-2.0) are read-only references; Apple's dyld/xnu/objc4/Libc/CF are APSL-2.0 and GPL-incompatible. Out-of-process oracles/tools are fine; copied code is not. Reimplement the Darling RPC protocol from its documentation if you want the design.
2. **Do not ship any Apple binaries or decrypted apps.** No IPSW contents, system dylibs, dyld, shared cache, firmware, decrypted IPAs, or decryption utilities in the repo or releases. Make the user supply the IPSW and decrypted binaries; gitignore `*.ipsw`; document the license obligations (§8). Also do not implement FairPlay decryption as a product feature.
3. **Do not chase the whole OS/GUI.** Darling's GUI gap is the decade-long trap. iOS 6 UIKit/CoreAnimation/WebKit is enormous; scope to a subset of apps (games/utility) and fail loudly on unimplemented selectors (`panic` with class/selector names, touchHLE's `UnimplementedClass`) rather than silently returning nil.
4. **Do not use one cooperative coroutine scheduler as the only threading model.** It is fine for single-threaded games and is a great bring-up model, but iOS 6 apps use GCD and may spin/lock-free. Provide real host threads per guest thread (or a hybrid with preemption at backedges/syscalls and a big lock) and virtualize all blocking primitives, or you will get deadlocks that look like app bugs.
5. **Do not ship a persistent cache without invalidation.** Key on guest bytes hash + translator version + settings + host CPU; handle SMC (page-protect or mtrack) and JIT-ing guests (JavaScriptCore, Mono/Unity); bound the cache size and evict (Box64's LRU limit, FEX's early unbounded-growth bug). A stale translation cache is a silent correctness bug.
6. **Do not assume ARMv7 == ARMv7s, or that an ARMv6-tested engine covers ARMv7-A.** Measure VFP/NEON (`vadd/vmul/vldm/vstm`, `vmov` between core and VFP), `idiv`, `LDREX/STREX`, `DMB/DSB/ISB`, unaligned `LDRD/STRD`, and Thumb-2 IT blocks against hardware/Unicorn before trusting any engine (dynarmic's own docs say ARMv6K; touchHLE has only tested ARMv6). And do not forget the ABI details of `objc_msgSend` struct returns and FP argument registers.
